# XFF2 parser and relocation stage

## Scope

This stage implements the container parser and the module-order relocation pass for the PAL retail profile `SCES-53326 v1.00`. The boot ELF and all three XFF inputs must come from a locally prepared copy of that exact disc build; the tools verify each module's expected size and SHA-256 before parsing it.

The implementation is host-side Python. No ISO, ELF, XFF module, generated object, or game asset is stored in the repository.

## Format handling

`tools/xff2.py` reads the `xff2` header and its file-offset tables, then validates section headers, biased image pointers (`0x40010000 + file offset`), string references, symbol indexes, relocation descriptors, target sections, and every relocation site. The supported relocation records are the four used by this game build:

- `R_MIPS_32` (2)
- `R_MIPS_26` (4)
- `R_MIPS_HI16` (5)
- `R_MIPS_LO16` (6)

HI16 records are paired with a later LO16 for the same symbol, with MIPS signed-low carry adjustment. Modules are linked in loader order: KERNEL, MANAGER, GAMECORE. Exports from earlier modules resolve imports in later modules. An import that is still unresolved uses the documented loader trap address `0x001B28F8` for the link-time image, and its original word, patched word, symbol, relocation kind, module, and guest address are preserved in `runtime_relocations.json` for a later runtime-linking implementation.

## Run locally

First extract the four inputs using the disc validator:

```sh
python3 tools/inspect_disc.py /path/to/your/SCES-53326.iso --extract-dir build/game-input
```

Then run the XFF relocation stage:

```sh
python3 tools/link_xff.py --files build/game-input --out build/xff-linked
```

Outputs are local-only and ignored by Git:

- `sotc_linked.elf`: ELF32 little-endian MIPS executable with the retail boot entry, allocated boot/module sections, load segments, and a merged symbol table.
- `sotc_functions.csv`: named function ranges from XFF function symbols and KERNEL's absolute boot-ELF symbols, in the CSV layout accepted by the pinned PS2Recomp parser.
- `runtime_relocations.csv`: code import sites (`j26`, `hi16`, `lo16`) passed to PS2Recomp for runtime rebinding. The pinned parser does not accept `w32`, so R_MIPS_32 code sites are counted in the manifest but omitted from this CSV.
- `sotc_recomp.toml`: initial PS2Recomp configuration pointing to the ELF, function map and runtime relocation list.
- `runtime_relocations.json`: static unresolved-import report, including the link-time trap word and original instruction word.
- `link_manifest.json`: module addresses, entry points, allocated sections, counts, output ELF hash and known limitations.
- `sections/*.bin`: section bytes after the static relocations have been applied.

Run the generated recompilation configuration from the output directory, using a host build of the pinned PS2Recomp revision:

```sh
cd build/xff-linked
/path/to/ps2recomp sotc_recomp.toml
```

PS2Recomp's analyzer/recompiler are host tools. The Android CI currently compiles the app and runs Python tests; it does not run the full game recompiler because a matching local disc image is required.

## Validation boundary

The synthetic test suite verifies XFF table bounds, symbol parsing, section indexing, module-order export resolution, all four relocation types, ELF32/MIPS headers, load segments, BSS representation and function-map output. It does **not** prove that the real disc modules link byte-for-byte correctly. That still requires a locally supplied matching disc and comparison against a PCSX2/ARMSX2 guest-memory dump at a known game state.

The merged ELF is now generated by the tool, but it has not yet been opened by the pinned PS2Recomp analyzer on real game inputs. Dynamic relocation handling for imports later supplied by the game's data archive remains a runtime responsibility.
